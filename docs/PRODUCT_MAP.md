## MCP tools

- **add_opportunity_occurrence** (write): Adds one of the user's opportunity Behaviors (is_opportunity true, running, not archived) to today: at an exact start_time, in a time range (start_time and end_time, or a preset), or, with mark_completed, as done now, marked Completed at the current minute. It adds a new Occurrence and changes no schedule. When a rule stops it, nothing changes and `refusal` says why. remove_opportunity_occurrence takes back an item added by mistake. Services: `lib/services/opportunity-integration.service.ts`.
- **archive_behavior** (write): Archives a Behavior so it schedules no new Occurrences, with an optional archive note. History, notes, and past Occurrences are kept, and restore_behavior reverses it. Archiving a parent Behavior also archives its active sub-behaviors. Nothing is deleted. Archiving an archived Behavior changes nothing. Services: `lib/services/integration-write.service.ts`.
- **create_behavior** (write): Creates a Behavior, a recurring thing the user wants to track (a habit, routine or recurring task), with schedules (daily, every N days, weekly or every N weeks on chosen weekdays, monthly on day N) and reminders. With is_opportunity true it can be added to today when there is room, and schedules may be empty. `sub_behaviors` creates a parent and up to {L.maxInlineSubBehaviors} sub-behaviors in one change; `parent_behavior_id` adds one sub-behavior to an existing parent, and one that follows the parent's schedule needs no `schedules`. An opportunity Behavior is never in a routine. list_categories lists categories. Services: `lib/services/integration-write.service.ts`.
- **end_behavior** (write): Ends a Behavior this minute. It stays active, moves to Not running, and schedules nothing more; its Unresolved Occurrences later today, including a window still open, are removed. Marked, noted, and timed Occurrences stay. To end on a later day, use update_behavior with end_on. resume_behavior starts it again. Ending an ended Behavior changes nothing. Services: `lib/services/integration-write.service.ts`.
- **fetch** (read): Returns the full text of one `search` result: a Behavior's definition, an Occurrence and its note, or a day note. Use it after `search` to read a result. {DAY_NOTE_MEANING} Services: `lib/services/integration-read.service.ts`.
- **get_account_context** (read): Returns the account's timezone, today's local date and time, the permissions this connection has, and how fresh the data is. Use it first to learn what "today" means for this user and which Cadence tools the connection may call. Services: `lib/services/integration-read.service.ts`.
- **get_adherence_summary** (read): Returns Completed, Not Completed, and Unresolved counts and the adherence rate, overall and per Behavior, for a date range of up to {L.maxAdherenceRangeDays} days. {ADHERENCE_DEFINITION} Counts and the rate cover scheduled Occurrences; opportunity_completed_count counts added opportunities apart. Use it for "how am I doing" questions. Cadence does not compute streaks. Services: `lib/services/integration-read.service.ts`.
- **get_behavior** (read): Returns one Behavior's full definition: schedules and time entries, reminder settings, category, description, location, default duration, run state, end, pause, archive notes, parent link, sub-behaviors, and revision. Use it before editing a Behavior. Services: `lib/services/integration-read.service.ts`.
- **get_occurrence** (read): Returns one Occurrence with its note, full status history, measured time sessions, and revision. Use it before changing an Occurrence's status or note. Services: `lib/services/integration-read.service.ts`.
- **get_timeline** (read): Returns the Timeline as the Cadence web app groups it: Needs decision (Unresolved Occurrences from before today) plus each day's Occurrences, with parent Behavior slots and their derived progress in `parent_groups`. Use it for questions such as "what's on today" or "what still needs a decision". Covers up to {L.maxTimelineDays} days from the start date. Services: `lib/services/integration-read.service.ts`.
- **list_behaviors** (read): Lists the user's Behaviors, the recurring things they track (habits, routines, or recurring tasks), with schedules, reminders, category, run state, archive notes, and sub-behavior links. A parent Behavior lists its sub-behaviors (one level deep). Use it to find a Behavior id or review what the user tracks. Includes archived Behaviors unless filtered. Services: `lib/services/integration-read.service.ts`.
- **list_categories** (read): Lists the user's Behavior categories in display order. Use it to choose a category id when creating or editing a Behavior. Services: `lib/services/integration-read.service.ts`.
- **list_day_notes** (read): Lists the user's day notes for a date range of up to {L.maxDayNoteRangeDays} days. {DAY_NOTE_MEANING} Use it for questions about how a day went overall. Only dates with a saved note are returned. Services: `lib/services/integration-read.service.ts`.
- **list_occurrences** (read): Lists Occurrences (single scheduled instances of a Behavior, such as one day's habit check-in) over a date range of up to {L.maxOccurrenceRangeDays} days, filtered by status or Behavior. Use it for history questions or to find an Occurrence id. Results are ordered by date and time. Services: `lib/services/integration-read.service.ts`.
- **move_occurrence_for_day** (write): Moves one of today's Unresolved Occurrences to another start time today. Only that day changes: the Behavior's schedule and the planned time stay the same, and `effective_start_at` shows the new time. The item keeps its length. Reminders follow the new time. Send the `revision` you last read as `expected_revision`. When a rule stops the move (the time has passed, something else is already there, the item changed since you read it), nothing changes and `refusal` explains why and offers up to three free times. Use revert_occurrence_move to undo it. Services: `lib/services/occurrence-move-integration.service.ts`.
- **pause_behavior** (write): Pauses a Behavior from from_on until back_on, when it runs again by itself from the start of that day. A pause can start today or later; today starts now unless from_time is later. A Behavior has one pause at a time: a new pause replaces the old one. No Occurrences are scheduled while paused, and Unresolved ones inside the pause are removed. Marked, noted, and timed Occurrences stay. Services: `lib/services/integration-write.service.ts`.
- **remove_opportunity_occurrence** (write): Removes an opportunity Occurrence that was added to a day, today or still in Needs decision, and cancels its pending reminders. The Behavior stays available as an opportunity. Only a clean item can be removed: Unresolved, never marked, with no note, tracked time or connected activity. A scheduled Occurrence is never removed. When a rule stops it, nothing changes and `refusal` says why. Services: `lib/services/opportunity-integration.service.ts`.
- **restore_behavior** (write): Restores an archived Behavior so it schedules Occurrences again from today. Archive notes are kept. Restoring a parent Behavior also restores the sub-behaviors archived with it; a sub-behavior of an archived parent can't be restored on its own. Restoring an active Behavior changes nothing. Services: `lib/services/integration-write.service.ts`.
- **resume_behavior** (write): Runs a paused or ended Behavior again from now: it clears the pause, and an end that has passed. An end still to come stays. Resuming a running Behavior changes nothing. Use restore_behavior for an archived Behavior. Services: `lib/services/integration-write.service.ts`.
- **revert_occurrence_move** (write): Undoes the latest move of one of today's Unresolved Occurrences, putting it back where it was before that move: its planned time, or an earlier move. Only the latest move can be undone. When there is nothing to undo or the item changed since you read it, nothing changes and `refusal` explains why. Services: `lib/services/occurrence-move-integration.service.ts`.
- **search** (read): Searches the user's Behaviors (titles, descriptions, archive notes), Occurrence notes, and day notes by text. Returns ids for `fetch` and links into the Cadence web app. Use it to find a habit, routine, or note by keyword. {DAY_NOTE_MEANING} Services: `lib/services/integration-read.service.ts`.
- **set_occurrence_status** (write): Marks one Occurrence Completed or Not Completed, or returns it to Unresolved. Use it when the user says they did, or did not do, a scheduled habit, routine, or task. Setting the current status again changes nothing. Each change is kept in the status history. Services: `lib/services/integration-write.service.ts`.
- **set_parent_occurrence_status** (write): Marks every sub-behavior Occurrence in one parent Behavior slot Completed or Not Completed in one change, such as a whole skin routine one morning. Name the slot with `local_date`, plus `slot_key` from get_timeline `parent_groups` when the parent has several times that day, or list `occurrence_ids`. Occurrences that already have the status do not change. To mark one step, use set_occurrence_status. Services: `lib/services/integration-write.service.ts`.
- **update_behavior** (write): Edits a Behavior's title, description, place, category, schedules, reminders, length, end, opportunity flag or sub-behavior link. Only the fields sent change; `schedules` replaces the whole list and may be empty only for an opportunity Behavior. `parent_behavior_id` groups it under a parent, or null makes it top-level; `sub_behavior_sort_order` moves it among its siblings. An opportunity Behavior is never part of a routine. A parent's schedule change also reaches the sub-behaviors that follow it. Past and resolved Occurrences are kept. Read get_behavior first for the revision. Services: `lib/services/integration-write.service.ts`.
- **update_day_note** (write): Adds, replaces, or clears the user's one note for a calendar date. {DAY_NOTE_MEANING} Use update_occurrence_note for one scheduled instance and set_occurrence_status for Completed or Not Completed. Future dates are allowed. Services: `lib/services/integration-write.service.ts`.
- **update_occurrence_note** (write): Adds, replaces, or clears the note on one Occurrence. Use it when the user wants to record context about a specific scheduled instance, such as how a workout went. Services: `lib/services/integration-write.service.ts`.
