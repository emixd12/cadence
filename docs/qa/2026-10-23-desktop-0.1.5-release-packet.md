## Why 0.1.5

On October 23, PR #111 (read-only Outlook, iCloud and Hevy connectors) and PR #112
(Ticket 215, Behavior Where) reached main, and their hosted migrations were applied.
The hosted Behavior writer now requires `where_kind` in every desktop upsert.
Published 0.1.3 (SQLite schema 17) does not send it, so its Behavior sync fails
closed with "Update Cadence". Local data stays on the Mac.

0.1.5 restores Behavior sync. It is newer than every published version (0.1.3).
Version 0.1.4 was never built or published; its session fix ships here.

Desktop changes since the 0.1.3 source `dcefe7e`:

- PR #115: the 0.1.4 linked-session callback fix.
- PR #111: Outlook Calendar, iCloud Calendar and Hevy panels, their disposable
  caches in `calendar-cache.sqlite3`, and Timeline context.
- PR #112: SQLite migration `0018_behavior_where.sql` (schema 18) and the Where
  sync contract. Existing location text becomes Where = A place.
- PR #134: the Hardened Runtime location entitlement
  `com.apple.security.personal-information.location` (Ticket 165).
- Dependency updates, including `rustls` 0.23.46.

The travel release train (PR #138, desktop schema 19–20) names 0.1.5 as its minimum
desktop version. It will move to 0.1.6; this packet does not edit #138.

## Connector gating

Determined October 23 from main `f922685` and the production deployment.

The desktop has no client-side connector flag. A production build with a broker
origin renders Outlook Calendar, iCloud Calendar and Hevy in Settings → Connectors
for a linked account. The hosted broker at `https://app.cadence-me.com` decides the
state of each one.

Production has none of the connector secrets. `vercel env ls production` lists no
`CONNECTOR_CREDENTIAL_*` and no `OUTLOOK_CALENDAR_*` names (names only; no values
were read). The connector routes exist: unauthenticated requests to
`/api/{hevy,outlook-calendar,icloud-calendar}/connection` return 401, and an
unknown path returns 404. Without the keyring, `getConnectorConnection` reports
`not_configured` for all three. Outlook also reports it without its OAuth settings.

What a 0.1.5 user sees:

| Mode | Settings → Connectors | Timeline | Daily Brief settings |
|---|---|---|---|
| Local (no account) | Each panel: "Link a Cadence account on this Mac to connect …" | Nothing from the three sources | Unchanged |
| Linked account | Each panel: "… connection is not configured." and "… not configured for this Cadence deployment." No key, password or connect controls | Nothing; `not_configured` is not an active Timeline state | The three disclosures stay hidden; they appear only for a connected source or one already turned on |

The web app at app.cadence-me.com shows the same linked-account state today.
Conclusion: no unaccepted connector is usable, and none is broken. The panels are
visible but say plainly that the connection is not configured.

Enablement is server-side only. Setting the `CONNECTOR_CREDENTIAL_*` keyring in
production would at once enable Hevy and iCloud on web and on every installed 0.1.5
or later desktop. Outlook also needs the `OUTLOOK_CALENDAR_*` settings. Installed
desktop connector checks (Keychain, `cadence://` deep links, per-source cache
cleanup) remain unverified, so enable these only after their own acceptance.
