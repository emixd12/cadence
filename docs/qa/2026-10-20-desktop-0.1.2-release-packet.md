# Cadence desktop 0.1.2 release packet — October 20, 2026

## State

Candidate `0.1.2` replaces the unpublished `0.1.1` candidate
([0.1.1 packet](2026-10-19-desktop-0.1.1-release-packet.md)). It is Developer ID
signed, notarized and stapled, and passes local artifact verification. It is **not
published**. The QA prerelease `desktop-updater-qa-20260928` holds its DMG and updater
files for installed acceptance, and its QA feed names `0.1.2`. No public feed,
marketing link or hosted setting changed.

## Why 0.1.1 was replaced

Installed acceptance of 0.1.1 on October 19–20 found two defects (Ticket 178):

1. **Stray sign-in callback.** Opening a replayed `cadence://auth/callback` while
   signed in replaced the linked state with an error. Sync reported a revoked
   session, and the Calendar client disappeared, showing "Calendar is unavailable in
   this build". Calendar actions silently did nothing until relaunch. The saved
   session was unharmed; relaunching recovered. Fixed in `4d9526f`: rejected
   callbacks keep the linked state and show an account notice.
2. **Refused restart message.** After the preview.51 → 0.1.1 update installed,
   Restart Cadence was refused while a save or sync ran. The reason appeared at the
   top of the window, and the owner did not see it. Fixed in `4d9526f`: the message
   appears beside the button and says to retry or to quit and reopen.

## Owner gates before publication

1. On the second Mac, install 0.1.2 from the QA page with a browser and open it normally.
2. On 0.1.2, repeat the sign-in callback replay. Expect a notice, a signed-in account
   and current sync. Repeat the Calendar callback replay, then Calendar authorization
   expiry (wait more than 5 minutes on the consent page).
3. Remote sign-out of the test account, then confirm Reconnect without data loss.
4. On the owner Mac, run 0.1.2 signed in for more than an hour, then confirm sync is
   still current (session renewal).
5. Merge PR #115 so main matches the shipped source, then the owner's publish instruction.
