# Status archive

`STATUS.md` at the repository root holds current state only: the open-work table and
the newest dated entries. Older entries live here, moved unchanged. Search these files
with grep; do not read them in full.

## Layout

- `archive/YYYY-MM.md`: one file per month. Each holds the entries whose `##` heading
  carries a date in that month, newest first, in their original relative order.
- `archive/legacy-current-repository-state.md`: the former "Current repository state"
  section of `STATUS.md` and every section after it, as they stood on November 9, 2026.

## Rules

- An entry starts at a `##` heading with a date ("November 7, 2026", "November 6–7, 2026"
  or "2026-09-09"). The script files it under the month of the last date in the heading;
  a range counts as its first day.
- A `##` section with no date in its heading belongs to the dated entry above it and
  moves with it. Example: "Function" moved with "Ticket 186: Cadence project and
  repository rename — completed October 9, 2026" into `archive/2026-10.md`.
- The one-time split on November 9, 2026 (Ticket 286) moved "Update rules" into
  `STATUS.md` and moved "Current repository state" through the old end of the file into
  the legacy file, unchanged. That block is mostly undated; its one dated section
  ("Desktop repair acceptance — 2026-09-09") stayed in the legacy file with its context.
- Never delete or reword archived text.

## Archiving

- `npm run status:archive` moves the oldest entries from "Recent entries" in `STATUS.md`
  into the monthly files until `STATUS.md` is at most 30,000 bytes. It always keeps the
  3 newest entries, then regenerates the index below. A second run changes nothing.
- `npm run status:archive -- --check` exits 1 when `STATUS.md` is above 40,000 bytes.
  `npm run agents:check` enforces the same limit.
- `npm run status:archive -- --index` regenerates the index only.
